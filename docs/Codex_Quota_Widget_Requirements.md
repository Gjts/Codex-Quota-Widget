## 1. 项目背景

Codex Quota Widget 是一个跨平台桌面悬浮小组件，用于实时展示本机 Codex 的额度状态，包括「5小时额度」和「每周额度」。

普通额度展示通常只有冷冰冰的数字、百分比和重置时间。这个项目的差异化在于：将 Codex 额度转译成修仙世界观中的「灵力」「道蕴」「灵脉复苏」「闭关恢复」「渡劫预警」等概念，并通过小精灵、玉牌、命灯等视觉形象持续陪伴用户。

它不是一个复杂的 IDE 插件，而是一个轻量桌面挂件，核心价值是：

1. 让用户不用切换窗口，也能看到 Codex 剩余额度。
2. 让用户知道当前是否适合开启大任务。
3. 在额度快耗尽时及时提醒，避免工作流被突然打断。
4. 用有趣的修仙皮肤降低额度焦虑，提高产品记忆点。
5. 为后续扩展 AI 工具额度管理打基础。

## 2. 产品定位

### 2.1 一句话定位

Codex Quota Widget 是一个修仙风 Windows / macOS 桌面悬浮小组件，把 Codex 的 5小时额度和每周额度变成「灵力」与「道蕴」，通过小精灵状态、倒计时和低额度提醒，帮助开发者规划 AI 编程额度。

### 2.2 产品关键词

- Codex 额度
- 桌面悬浮窗
- Tauri 跨平台桌面应用
- Windows / macOS
- 修仙风
- 小精灵陪伴
- 5小时额度
- 每周额度
- 灵力 / 道蕴
- AI Coding 工具管理

### 2.3 产品不是做什么

MVP 阶段不做以下内容：

- 不做完整 IDE 插件。
- 不做通用 API Billing Dashboard。
- 不做多模型复杂账单系统。
- 不做团队额度管理后台。
- 不做云同步账户系统。
- 不做复杂商城皮肤系统。
- 不做 AI 代码生成能力。
- 不承诺一定能自动读取所有 Codex 版本的额度数据。

MVP 的原则是：先让桌面小组件可用、好看、能提醒。别一上来把一个额度挂件做成天庭财政部，凡人项目通常死在这里。

## 3. 目标用户

### 3.1 核心用户

#### 独立开发者

- 高频使用 Codex / Claude Code / Cursor / 其他 AI Coding 工具。
- 经常集中冲刺项目。
- 需要知道今天和本周还能使用多少额度。
- 希望通过桌面挂件减少切换窗口。

#### AI 编程重度用户

- 使用 Codex CLI 或类似命令行工具。
- 经常进行大规模重构、生成测试、代码审查。
- 容易在连续任务中突然触发额度限制。
- 希望提前知道当前额度风险。

#### 一人公司 / 副业开发者

- 白天工作，晚上开发产品。
- 周末集中使用 Codex。
- 需要合理安排每周额度。
- 对可爱、有情绪记忆点的小工具接受度高。

### 3.2 次级用户

#### 效率工具爱好者

- 喜欢桌面 Widget。
- 喜欢托盘工具。
- 喜欢透明悬浮窗。
- 愿意为好看、好玩、低打扰的小工具长期保留。

#### 内容创作者 / 产品经理

- 想把 AI 使用状态可视化。
- 可能用于视频、图文内容截图。
- 对修仙风主题有传播兴趣。

## 4. 核心问题

### 4.1 用户痛点

1. Codex 额度不够直观。
2. 用户不想频繁打开终端或网页查看额度。
3. 大任务开始前不知道额度是否足够。
4. 额度耗尽时工作被打断。
5. 周额度缺少规划感。
6. 现有额度提示没有情绪反馈，记忆点弱。
7. 桌面端缺少一个长期可见的轻量额度状态入口。

### 4.2 典型失败场景

用户晚上准备让 Codex 重构一个模块，任务进行到一半额度耗尽。此时用户才发现 5小时额度只剩很少，周额度也已经告急。项目被迫中断，节奏崩掉。

Codex Quota Widget 要解决的就是这件事：在用户开大任务之前，先告诉他「灵力是否足够」。

## 5. 产品目标

### 5.1 MVP 目标

MVP 只验证一个核心假设：

> 用户是否愿意长期在桌面上保留一个 Codex 额度悬浮小组件？

MVP 必须完成：

- Windows / macOS 可运行。
- 有一个透明悬浮小窗。
- 能展示 5小时额度与每周额度。
- 能展示重置倒计时。
- 能手动录入或更新额度。
- 能在低额度时提醒。
- 有至少 1 套修仙主题皮肤。
- 有托盘入口。
- 本地保存设置。

### 5.2 V1.0 目标

V1.0 在 MVP 基础上增强可用性：

- 自动读取或半自动解析 Codex 额度。
- 支持多套皮肤。
- 支持开机自启。
- 支持鼠标穿透。
- 支持快捷键显示 / 隐藏。
- 支持额度恢复提醒。
- 支持基础历史记录。
- 支持使用趋势和风险预测。

### 5.3 长期目标

长期可以扩展为：

- 多 AI 工具额度管理器。
- Codex / Claude / Cursor / OpenAI API 统一桌面额度面板。
- AI Coding 使用习惯分析工具。
- 个人 AI 编程生产力仪表盘。

## 6. 核心概念设计

### 6.1 额度概念映射

| Codex 概念 | 产品显示 | 修仙表达 | 说明 |
|---|---|---|---|
| 5小时额度 | 当前短期额度 | 小周天灵力 | 当前周期可用 Codex 能量 |
| 每周额度 | 本周总额度 | 大周天道蕴 | 本周总体资源池 |
| 剩余额度 | Remaining | 剩余灵力 | 可继续调用的额度 |
| 已用额度 | Used | 已耗真元 | 已经消耗的额度 |
| 重置时间 | Reset Time | 灵脉复苏 | 额度恢复时间 |
| 额度耗尽 | Exhausted | 灵脉枯竭 | 不能继续调用 |
| 低额度 | Warning | 道基不稳 | 需要谨慎使用 |
| 恢复完成 | Restored | 灵气回潮 | 可以继续使用 |

### 6.2 状态等级

#### 5小时额度状态

| 剩余比例 | 状态名称 | 修仙文案 | UI 状态 |
|---:|---|---|---|
| 80%-100% | Excellent | 灵气充盈 | 发光、轻动效 |
| 50%-79% | Normal | 灵力稳定 | 正常状态 |
| 20%-49% | Warning | 真元偏弱 | 轻微暗淡 |
| 1%-19% | Danger | 道基不稳 | 红色提示、抖动 |
| 0% | Exhausted | 灵脉枯竭 | 灰色、闭关状态 |

#### 每周额度状态

| 剩余比例 | 状态名称 | 修仙文案 | 建议 |
|---:|---|---|---|
| 70%-100% | 充足 | 本周道蕴充沛 | 可以正常使用 |
| 40%-69% | 正常 | 道蕴尚可 | 适合中型任务 |
| 20%-39% | 偏低 | 宗门资源偏紧 | 保留给重要任务 |
| 1%-19% | 危险 | 本周大限将至 | 只用于关键任务 |
| 0% | 耗尽 | 本周闭关 | 等待周重置 |

## 7. 核心功能需求

## 7.1 悬浮小组件

### 功能描述

应用启动后显示一个可拖拽的桌面悬浮窗口，默认置顶，展示 Codex 额度状态。

### 功能细节

- 无边框窗口。
- 透明背景。
- 可拖动。
- 可锁定位置。
- 支持始终置顶。
- 支持隐藏到托盘。
- 支持最小化显示。
- 支持多显示器位置记忆。
- 支持透明度调节。
- 支持窗口尺寸缩放。
- 支持鼠标穿透模式，V1.0 实现。
- 支持开机自动启动，V1.0 实现。

### 验收标准

- 用户可以拖动悬浮窗到任意位置。
- 关闭窗口不会退出应用，而是隐藏到托盘。
- 重启应用后恢复上次位置。
- 在 Windows 和 macOS 上窗口表现基本一致。
- 透明窗口不会出现明显白底或黑底。

---

## 7.2 额度展示

### 功能描述

悬浮窗展示 5小时额度和每周额度。

### 展示字段

#### 5小时额度

- 剩余百分比。
- 已用百分比。
- 重置倒计时。
- 状态文本。
- 状态颜色。
- 修仙文案。

#### 每周额度

- 剩余百分比。
- 已用百分比。
- 周重置倒计时。
- 状态文本。
- 状态颜色。
- 修仙文案。

### 展示形式

默认标准模式：

```text
灵力 68%   02:14:32
道蕴 41%   3天12时
状态：灵力稳定
```

迷你模式：

```text
🦊 68% / 41%
```

完整模式：

```text
Codex 灵脉状态

小周天灵力：68%
复苏倒计时：02:14:32

大周天道蕴：41%
轮回倒计时：3天12时
```

### 验收标准

- 百分比变化后 UI 实时刷新。
- 倒计时每秒更新。
- 低额度时视觉状态变化。
- 周额度与 5小时额度明确区分。
- 用户不会把两个额度看混。

## 7.3 手动额度录入

### 功能描述

MVP 阶段允许用户手动录入额度数据。

### 字段

- 5小时额度剩余百分比。
- 5小时重置时间。
- 每周额度剩余百分比。
- 每周重置时间。
- 数据更新时间。

### 输入方式

- 设置页表单输入。
- 快捷编辑模式。
- 复制文本后自动识别，V1.0 实现。

### 表单规则

- 百分比必须在 0 到 100 之间。
- 重置时间必须大于当前时间。
- 未填写周额度时允许只显示 5小时额度。
- 未填写 5小时额度时允许只显示周额度。
- 错误输入需要给出提示。

### 验收标准

- 用户可以在 1 分钟内完成初始配置。
- 配置保存后重启应用不丢失。
- 错误输入不会导致应用崩溃。
- 修改额度后悬浮窗立即更新。

## 7.4 半自动解析额度

### 功能描述

用户复制 Codex 或终端中的 quota 文本，粘贴到应用中，应用自动解析字段。

### 示例输入

```text
5h remaining: 68%
weekly remaining: 41%
reset in: 2h 14m
weekly reset: 3d 12h
```

### 解析目标

- 识别 5h / 5 hour / five hour。
- 识别 weekly / week。
- 识别 remaining / left / remain。
- 识别 reset in / reset at。
- 支持中英文混合。
- 不识别时保留原文并提示用户手动确认。

### MVP 状态

- MVP 可不做。
- V1.0 建议实现。

### 验收标准

- 常见英文格式可以解析。
- 解析结果进入确认页。
- 用户确认后才写入状态。
- 解析失败不会覆盖原状态。

## 7.5 自动读取额度

### 功能描述

尝试从本机 Codex CLI、本地配置、日志或命令输出中读取 quota 信息。

### 数据来源策略

1. 优先读取已知本地状态文件。
2. 如无状态文件，尝试执行安全白名单命令。
3. 如失败，回退到手动模式。
4. 所有自动读取结果必须保留来源与更新时间。

### 重要说明

不同 Codex 版本的数据路径和输出格式可能变化，因此自动读取不能作为 MVP 的唯一数据来源。MVP 必须保留手动模式。人类软件最大骗局之一就是「应该能自动读到」，听起来美好，实际通常在用户电脑上当场翻车。

### 验收标准

- 自动读取失败时不影响应用启动。
- 失败原因可以在设置页查看。
- 用户可以关闭自动读取。
- 用户可以手动刷新。
- 支持读取周期配置。

## 7.6 低额度提醒

### 功能描述

当 5小时额度或每周额度低于用户设定阈值时，触发提醒。

### 默认阈值

| 等级 | 5小时额度 | 每周额度 | 行为 |
|---|---:|---:|---|
| Warning | 30% | 30% | UI 状态变化 |
| Danger | 15% | 15% | 桌面通知 |
| Exhausted | 0% | 0% | 强提示 |

### 提醒方式

- 小组件状态变化。
- 桌面系统通知。
- 托盘图标提示。
- 可选音效，后续实现。
- 可选动画抖动，MVP 可做轻量版。

### 提醒频率控制

- 同一阈值每个周期只提醒一次。
- 用户手动刷新后如果仍处于同一状态，不重复轰炸。
- 额度恢复后重置提醒状态。
- 用户可关闭所有通知。

### 修仙提醒文案

#### Warning

- 灵力不足 30%，建议谨慎开阵。
- 当前真元偏弱，适合处理小任务。
- 本周道蕴消耗偏快，请留给关键任务。

#### Danger

- 灵力不足 15%，道基开始摇晃。
- 再召唤几次，可能进入闭关恢复。
- 本周大限将至，别拿额度改变量名了。

#### Exhausted

- 灵脉枯竭，等待复苏。
- 今日小周天已尽，请稍后再战。
- 本周道蕴耗尽，建议闭关整理需求文档。

### 验收标准

- 阈值触发准确。
- 通知不会频繁骚扰用户。
- 用户可以关闭通知。
- 低额度时皮肤状态明显变化。

## 7.7 皮肤系统

### 功能描述

通过主题皮肤呈现不同修仙风视觉。

### MVP 皮肤

MVP 推荐只做 1 套：

#### 灵狐小管家

- 额度充足：灵狐摇尾，灵气粒子。
- 额度正常：灵狐待机。
- 额度偏低：耳朵下垂。
- 额度危险：抱着空灵石。
- 额度耗尽：趴下睡觉。

### V1.0 皮肤

#### 宗门玉牌

- 更简洁。
- 信息密度高。
- 适合工具型用户。
- 可以作为专业模式。

#### 命灯器灵

- 命灯亮度表示额度。
- 氛围感强。
- 适合长期挂桌面。

#### 雷劫渡劫云

- 强提醒型。
- 适合趣味传播。
- 不建议默认开启。

### 皮肤状态统一规范

每个皮肤都必须支持以下状态：

- excellent
- normal
- warning
- danger
- exhausted
- restoring

### 验收标准

- 切换皮肤后数据不丢失。
- 每个状态有明显视觉差异。
- 皮肤动效不能明显影响性能。
- 用户可以关闭动效。

## 8. 页面设计

## 8.1 悬浮窗

### 迷你模式


## 9. 用户使用场景

## 9.1 开工前检查

用户打开电脑，Codex Quota Widget 自动启动，显示：

```text
灵力 92%
道蕴 83%
状态：灵气充盈
```

用户知道今天适合开启 Codex 大任务。

---

## 9.2 大任务前判断

用户准备让 Codex 分析整个项目。小组件显示：

```text
灵力 18%
道蕴 52%
状态：道基不稳
```

应用提示：

```text
当前灵力不足 20%，不建议开启大型法阵。
建议先处理小任务，等待灵脉复苏。
```

---

## 9.3 连续使用时提醒

用户连续用 Codex 修 bug、写测试、重构代码。额度低于 15%，灵狐变成抱着空灵石的状态，并触发通知：

```text
灵力不足 15%，再召唤几次可能进入闭关恢复。
```

---

## 9.4 额度耗尽

5小时额度归零，悬浮窗变灰：

```text
灵脉枯竭
复苏倒计时：00:42:18
```

应用建议：

```text
当前可先整理需求、拆分任务、写测试用例，等待额度恢复后再召唤 Codex。
```

---

## 9.5 周额度告急

本周额度低于 20%，应用提示：

```text
本周道蕴不足，建议把额度留给真正关键的问题。
```

用户减少无意义调用，把剩余额度留给上线前 bug 修复。

## 11. 非功能需求

### 11.1 性能要求

- 常驻内存尽量控制在合理范围内。
- 悬浮窗动画不能导致明显 CPU 占用。
- 倒计时刷新不能造成 UI 卡顿。
- 应用启动时间尽量小于 3 秒。
- 空闲状态 CPU 占用应接近 0。

### 11.2 安全要求

- 默认不上传任何数据。
- 所有额度信息仅保存在本地。
- 自动读取命令必须白名单控制。
- 不允许执行用户输入的任意 shell 命令。
- 插件权限最小化配置。
- 如果未来支持联网更新，需要签名和版本校验。

### 11.3 隐私要求

- 不收集源码内容。
- 不收集 Codex 对话内容。
- 不收集用户项目路径，除非用户主动开启自动读取。
- 所有历史记录默认本地保存。
- 提供一键清除本地数据。

### 11.4 兼容性要求

- Windows 10 / 11。
- macOS 13+ 优先。
- 支持高 DPI 显示器。
- 支持多显示器。
- 支持浅色 / 深色系统环境。
- 默认英文和中文文案可扩展，MVP 可先中文。

## 15. 产品风险

### 15.1 自动读取额度风险

Codex 本地额度数据可能没有稳定 API。不同版本 CLI 可能输出不同格式。

应对策略：

- MVP 优先手动模式。
- V1.0 做半自动解析。
- 自动读取作为增强能力，不作为核心依赖。

### 15.2 Tauri 跨平台窗口差异

透明窗口、置顶、托盘、点击穿透在 Windows 和 macOS 上可能表现不同。

应对策略：

- 尽早双平台测试。
- MVP 先保证透明 + 置顶 + 托盘。
- 鼠标穿透放到 V1.0。
- 对不同平台做能力降级。

### 15.3 主题动效过重

小精灵动画如果做得太复杂，会影响性能。

应对策略：

- MVP 使用 CSS / SVG / 轻量 Lottie。
- 支持关闭动画。
- 状态表达优先，不追求复杂动画。
